# neon_branch_realtime_secret (Ephemeral Resource)

Retrieves a branch's Realtime shared signing secret without storing it in Terraform state or plan. Requires Terraform 1.10+ and permission to read project credentials. Returns the first successful response, including the previous usable secret when pending is true; does not rotate secrets or enable Realtime.

## Example Usage

```terraform
terraform {
  required_version = ">= 1.10"
}

resource "neon_project" "x" {
  name = "realtime-secret-example"
}

resource "neon_branch_realtime" "this" {
  project_id      = neon_project.x.id
  branch_id       = neon_project.x.branch.id
  allowed_origins = ["https://app.example.com"]
}

ephemeral "neon_branch_realtime_secret" "this" {
  project_id = neon_project.x.id
  branch_id  = neon_project.x.branch.id
  depends_on = [neon_branch_realtime.this]
}

# Pass ephemeral.neon_branch_realtime_secret.this.secret only to an
# ephemeral-capable consumer (for example a write-only provider argument).
# Do not write it to an ordinary output, local file, or persistent resource field.
# pending=true may accompany the previous usable secret during rotation.
```

Requires Terraform 1.10+ and a Neon API credential authorized to read the project's credentials. Keep the secret in ephemeral-capable consumers only. Sensitive marking is not permission to put it in an ordinary output, local file, logs, or persistent resource argument. This ephemeral resource has no persistent identity, import, cache, renewal, close operation, or rotation operation.

## Provisioning and plan-time access

Terraform may Open during plan as soon as project and branch IDs are known. Declare `depends_on = [neon_branch_realtime.this]` when enabling in the same configuration. If access still occurs before enablement is available, enable first with `terraform apply -target=neon_branch_realtime.this`, then apply consumers. Retries cannot enable an already-disabled branch.

A secret-endpoint 404 is retried without classifying its reason under a five-minute budget capped by the caller deadline. Exhaustion includes the last SDK 404 and timeout diagnostics. Other errors use the existing readiness/diagnostic policy; credential permission errors fail immediately. Polling is immediate, then at one-second intervals. In-flight SDK requests cannot be canceled and may overrun the scheduling budget by the provider transport's current two-minute timeout. There is no Terraform `timeouts` block.

## Pending semantics

The first successful response returns both `secret` and `pending`, even when pending is true. During a rotation the API returns the previous usable secret until completion; this resource neither initiates rotation nor waits for a new secret. Consumers must not assume pending means the returned value is post-rotation.
