# neon_branch_realtime_secret (Ephemeral Resource)

Reads the secret an application backend issues Neon Realtime tokens with. The secret is never stored in the Terraform state.

## Example Usage

```terraform
resource "neon_project" "realtime_secret" {
  name      = "realtime-secret-example"
  region_id = "aws-us-east-2"

  # Realtime enables logical replication on the project.
  enable_logical_replication = true
}

resource "neon_branch_realtime" "secret_example" {
  project_id = neon_project.realtime_secret.id
  branch_id  = neon_project.realtime_secret.default_branch_id
}

# Pass the secret to a write-only argument so it never reaches the state.
ephemeral "neon_branch_realtime_secret" "this" {
  project_id = neon_branch_realtime.secret_example.project_id
  branch_id  = neon_branch_realtime.secret_example.branch_id
}

resource "aws_ssm_parameter" "realtime_secret" {
  name             = "/neon/realtime/${neon_branch_realtime.secret_example.id}"
  type             = "SecureString"
  value_wo         = ephemeral.neon_branch_realtime_secret.this.secret
  value_wo_version = 1
}
```

## Schema

### Required

- `branch_id` (String) Branch ID. Realtime must be enabled on the branch.
- `project_id` (String) Project ID.

### Read-Only

- `secret` (String, Sensitive) Realtime secret, starting with `nrt_live_`.

## Realtime enabled in the same run

Terraform opens an ephemeral resource during plan as soon as its arguments are known. When the branch already exists and
the same run enables Realtime, the secret is read before Realtime is on, and the plan fails with "Neon Realtime not
enabled". Enable it first, then apply the rest of the configuration, for example for `neon_branch_realtime.this`:

```shell
terraform apply -target=neon_branch_realtime.this
terraform apply
```
