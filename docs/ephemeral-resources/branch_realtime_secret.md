# neon_branch_realtime_secret (Ephemeral Resource)

Reads the Realtime secret of a Neon branch without storing it in Terraform state or plan.

## Example Usage

```terraform
terraform {
  required_version = ">= 1.10"
}

resource "neon_project" "x" {
  name = "realtime-secret-example"
}

resource "neon_branch_realtime" "this" {
  project_id      = neon_project.x.id
  branch_id       = neon_project.x.branch.id
  allowed_origins = ["https://app.example.com"]
}

ephemeral "neon_branch_realtime_secret" "this" {
  project_id = neon_project.x.id
  branch_id  = neon_project.x.branch.id
  depends_on = [neon_branch_realtime.this]
}

# Pass ephemeral.neon_branch_realtime_secret.this.secret only to an
# ephemeral-capable consumer (for example a write-only provider argument).
# Do not write it to an ordinary output, local file, or persistent resource field.
# pending=true may accompany the previous usable secret during rotation.
```

Requires Terraform 1.10 or later and an API key that can read the project's credentials.
Pass the secret only to arguments that accept ephemeral values, such as write-only arguments or provider configuration.
Do not put it in outputs, files, or ordinary resource arguments.

## Timing

- Terraform can read the secret during plan once the project and branch IDs are known.
  Add `depends_on = [neon_branch_realtime.this]` when the same configuration enables Realtime.
- While Realtime is still provisioning, the read retries for up to five minutes.
- If Realtime is disabled on the branch, the read fails after the retries.
- A missing permission fails immediately.

## Rotation

- `pending` is `true` while a secret rotation is in progress.
- During a rotation the returned secret is the previous one, which keeps working until the rotation finishes.
- This resource does not rotate the secret.
