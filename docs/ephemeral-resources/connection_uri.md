# neon_connection_uri (Ephemeral Resource)

Ephemeral resource to retrieve the connection URIs of a Neon database for a role. The URIs contain the role's password and are never stored in the Terraform state.

## Example Usage

```terraform
resource "neon_project" "example" {
  name = "example"
}

# store the default connection URI to the AWS SSM Parameters Store instead of the terraform state
# using ephemeral resource
ephemeral "neon_connection_uri" "default" {
  project_id  = neon_project.example.id
  branch_id   = neon_project.example.branch.id
  endpoint_id = neon_project.example.primary_compute.id
  database    = neon_project.example.database_name
  role        = neon_project.example.database_user
  lifecycle {
    postcondition {
      condition     = self.uri != "" && replace(self.uri_pooler, "-pooler", "") == self.uri
      error_message = "URI is empty, or does not match URI pooler"
    }
  }
}

locals {
  secret_name = "${neon_project.example.id}/${neon_project.example.branch.id}/${neon_project.example.primary_compute.id}/${neon_project.example.database_user}/${neon_project.example.database_name}"
}

resource "aws_ssm_parameter" "default_neon_connection_uri" {
  name = "/neonConnectionURI/${local.secret_name}"
  type = "SecureString"
  value_wo = jsonencode({
    uri        = ephemeral.neon_connection_uri.default.uri
    uri_pooler = ephemeral.neon_connection_uri.default.uri_pooler
  })
  value_wo_version = 1
}
```

## Schema

### Required

- `database` (String) Database name.
- `project_id` (String) Project ID.
- `role` (String) Role name.

### Optional

- `branch_id` (String) Branch ID.
- `endpoint_id` (String) Endpoint ID.

### Read-Only

- `uri` (String, Sensitive) URI of the direct database connection. It contains the role's password.
- `uri_pooler` (String, Sensitive) URI of the pooled connection. It contains the role's password.

## Roles and databases created in the same run

Terraform opens an ephemeral resource during plan as soon as its arguments are known. When the project already exists
and the same run creates the role or database, the ephemeral resource is opened before it exists, and the plan fails with
"Neon role or database not found". Create it first, then apply the rest of the configuration, for example for a database in `neon_database.app` and the role it depends on:

```shell
terraform apply -target=neon_database.app
terraform apply
```
