# neon_role (Ephemeral Resource)

Ephemeral resource to retrieve the password of a Neon Postgres role. The password is never stored in the Terraform state.

## Example Usage

```terraform
resource "neon_project" "example" {
  name = "example"
}

# store the default role's password to the AWS SSM Parameters Store instead of the terraform state
# using ephemeral resource
ephemeral "neon_role" "default" {
  project_id = neon_project.example.id
  branch_id  = neon_project.example.branch.id
  name       = neon_project.example.database_user
  lifecycle {
    postcondition {
      condition     = self.password != ""
      error_message = "Empty role password returned"
    }
  }
}

locals {
  secret_name = "${neon_project.example.id}/${neon_project.example.branch.id}/${neon_project.example.database_user}"
}

resource "aws_ssm_parameter" "default_neon_role_password" {
  name             = "/neonRole/${local.secret_name}"
  type             = "SecureString"
  value_wo         = ephemeral.neon_role.default.password
  value_wo_version = 1
}
```

## Roles created in the same run

Terraform opens an ephemeral resource during plan as soon as its arguments are known. When the project already exists
and the same run creates the role, the ephemeral resource is opened before it exists, and the plan fails with
"Neon role not found". Create it first, then apply the rest of the configuration, for example for a role in `neon_role.app`:

```shell
terraform apply -target=neon_role.app
terraform apply
```
