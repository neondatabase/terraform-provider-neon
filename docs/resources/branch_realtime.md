# neon_branch_realtime (Resource)

Manages Realtime on a Neon branch, including inherited or already-enabled Realtime. Destroy disables Realtime on this branch and discards its shared secret; it does not restore the pre-adoption policy. Enable, update, and disable wait within a five-minute operation budget.

## Example Usage

```terraform
resource "neon_project" "x" {
  name = "realtime-example"
}

resource "neon_branch_realtime" "this" {
  project_id      = neon_project.x.id
  branch_id       = neon_project.x.branch.id
  allowed_origins = ["https://app.example.com"]
  # For any other branch, substitute neon_branch.example.id above.
  # Omit allowed_origins to preserve current/inherited policy without managing it.
  # [] and ["*"] both explicitly allow any origin.
}
```

Use `neon_project.x.branch.id` for the default branch, or any `neon_branch.example.id` for another branch. Children inherit enabled Realtime from their parent even when branch creation omits Realtime options. Enable is idempotent: this resource adopts inherited or externally enabled Realtime and applies configured origins without a separate existence check.

## Origins ownership

Omitted or null `allowed_origins` preserves current/inherited policy and stays null in state, including on import. Removing a configured list relinquishes management in place; it does not reset policy. Explicit `[]` and `["*"]` both allow any origin; refresh retains the configured spelling when the API returns the other unrestricted spelling. Other lists are refreshed without sorting or normalization so drift remains detectable. If GET omits origins, the previous managed list is retained with a warning that drift could not be observed. Origin syntax, counts, and wildcard combinations are validated by the API.

## Lifecycle and ownership

Enable/update waits for pending work to complete and requires enabled Realtime. Destroy disables this branch and discards its shared secret, including when creation adopted existing enablement. It does not restore pre-adoption origins or promise to undo inheritance on descendants. Refresh removes the resource after external disable or a 404, allowing a later apply to enable it again when its branch exists.

Operations have a five-minute scheduling budget capped by the caller deadline, with immediate polling followed by one-second waits and existing readiness retries. No Terraform `timeouts` block is provided. The SDK cannot cancel an in-flight HTTP request: the budget can overrun by one request, up to the current provider transport's two-minute timeout. Accepted enablement retains identity in state if subsequent polling fails, permitting refresh/destroy recovery.

The persistent resource exposes neither transient pending status nor secrets. Use the ephemeral `neon_branch_realtime_secret` resource for credential-authorized access; secret rotation is not managed here.

## Schema

### Required

- `branch_id` (String) The Neon branch ID. Changes require replacement.
- `project_id` (String) The Neon project ID. Changes require replacement.

### Optional

- `allowed_origins` (List of String) Browser origins to manage. Omitted or null preserves the current or inherited policy and leaves origins unmanaged. An explicit empty list or ["*"] allows any origin. The API validates origin syntax.

### Read-Only

- `enabled` (Boolean) Whether Realtime is enabled on the branch.
- `id` (String) Resource identity and import ID: <project_id>/<branch_id>.
- `invocation_url` (String) Application Realtime endpoint, or null when not returned by the API.
- `revision` (Number) Observed Realtime configuration revision, or null when not returned by the API.

## Import

Import exactly two non-empty components, `<project_id>/<branch_id>`. Origins remain unmanaged until explicitly configured.

```hcl
import {
  to = neon_branch_realtime.this
  id = "project-id/branch-id"
}
```

```shell
terraform import neon_branch_realtime.this 'project-id/branch-id'
```
