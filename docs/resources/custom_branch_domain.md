# neon_custom_branch_domain (Resource)

Manages custom domains for a project's branch.

## Example Usage

```terraform
resource "neon_project" "example" {
  name      = "foo"
  region_id = "aws-us-east-2"
}

resource "neon_function" "example" {
  project_id    = neon_project.example.id
  branch_id     = neon_project.example.branch.id
  slug          = "hello"
  runtime       = "nodejs24"
  name          = "hello"
  zip_file_path = "path/to/your/function/deployment.zip"

  environment_variables = {
    LOG_LEVEL = "info"
  }
}

resource "neon_custom_branch_domain" "example" {
  project_id  = neon_project.example.id
  branch_id   = neon_project.example.branch.id
  entity_type = "function"
  entity_id   = neon_function.example.slug
  domain      = "example.com"
}
```

## Schema

### Required

- `branch_id` (String) The branch ID.
- `domain` (String) The custom domain.
- `entity_id` (String) The target entity's identifier within the branch. For `function` this is the function slug (which must already exist on the branch).
- `entity_type` (String) The kind of branch entity the domain targets. Possible values: "function".
- `project_id` (String) The Neon project ID.

### Read-Only

- `cname_target` (String) The CNAME target provided by Neon to configure DNS for the custom domain to point to the resource, e.g., Neon function.
- `id` (String) The custom branch domain ID.



## Import

The Neon custom branch domain can be imported to the terraform state by its composite identifier that consists of
`ProjectID`, `BranchID` and `Domain` separated by a forward slash.

Import using the [import block](https://developer.hashicorp.com/terraform/language/import):

For example:

```hcl
import {
  to = neon_custom_branch_domain.example
  id = "curly-poetry-30604233/br-snowy-mountain-a5jkb18i/example.com"
}
```

Import using the command `terraform import`:

```commandline
terraform import neon_custom_branch_domain.example "curly-poetry-30604233/br-snowy-mountain-a5jkb18i/example.com"
```
