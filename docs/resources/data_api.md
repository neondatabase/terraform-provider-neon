# neon_data_api (Resource)

Manages a Neon Data API endpoint for a branch database. Authentication options apply only during creation; changes require replacement. Deletion does not revoke database grants or remove authentication schema objects created during setup.

## Example Usage

```terraform
resource "neon_project" "this" {
  name      = "data-api-example"
  region_id = "aws-us-east-2"
}

resource "neon_data_api" "this" {
  project_id    = neon_project.this.id
  branch_id     = neon_project.this.branch.id
  database_name = neon_project.this.database_name

  auth_provider = "neon_auth"

  settings = {
    db_schemas  = ["public"]
    db_max_rows = 100
  }
}

output "data_api_url" {
  value = neon_data_api.this.url
}
```

## Configuration and drift

Authentication options apply only during creation.
Changing them requires replacement and can interrupt requests to the endpoint.
GET does not return these options, so Terraform cannot detect external authentication changes or recover authentication values during import.

Only explicitly configured settings are managed.
Omitted members remain unmanaged instead of adopting API defaults.
Removing a managed setting requires replacement because the pinned SDK cannot send a reset request.
An explicit empty `db_schemas` list returns an SDK-mapping diagnostic rather than silently omitting the requested value.

Some backends return null settings or omit individual settings.
The provider retains last applied values and warns that it cannot detect remote drift for those members.
Deleting the endpoint does not revoke database grants or remove authentication schema objects created during setup.

## Schema

### Required

- `branch_id` (String) The Neon branch ID. Changes require replacement.
- `database_name` (String) The database served by the Data API. Changes require replacement.
- `project_id` (String) The Neon project ID. Changes require replacement.

### Optional

- `add_default_grants` (Boolean) Grant authenticated users permissions on public-schema tables during creation. Changes require replacement; deletion does not revoke these grants.
- `auth_provider` (String) Authentication provider: neon_auth or external. The API validates authentication configuration. Changes require replacement; GET cannot discover this value on import or detect external changes.
- `jwks_url` (String) JWKS endpoint for external JWT verification. Changes require replacement.
- `jwt_audience` (String) Expected JWT audience. Omit to skip audience validation. Changes require replacement.
- `provider_name` (String) Authentication provider display name. Changes require replacement.
- `settings` (Attributes) Mutable Data API settings. Only configured members are managed. Removing a managed member requires replacement because the SDK has no reset operation. Some backends return no settings, preventing remote drift detection. (see [below for nested schema](#nestedatt--settings))
- `skip_auth_schema` (Boolean) Skip auth schema and RLS function creation. Changes require replacement.

### Read-Only

- `id` (String) Resource identity and import ID: <project_id>/<branch_id>/<database_name>.
- `url` (String) The Data API endpoint URL used by applications.

## Import

Import using `<project_id>/<branch_id>/<database_name>`:

```hcl
import {
  to = neon_data_api.this
  id = "cool-moon-123/br-cool-moon-456/neondb"
}
```

Or use the CLI:

```commandline
terraform import neon_data_api.this "cool-moon-123/br-cool-moon-456/neondb"
```

Import reads identity and URL.
It leaves authentication options and settings null.
Adding settings after import starts managing those members with an update.
Adding creation-only options after import requires replacement.
Review the plan before applying.
