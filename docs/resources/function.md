# neon_function (Resource)

Manages a Neon Serverless Function on a branch.

~> **Note:** Neon Functions is a beta service. The schema may shift as the service evolves; see the [Neon Functions documentation](https://neon.tech/docs/functions/overview) for the current contract.

## Example Usage

```terraform
resource "neon_project" "example" {
  name      = "foo"
  region_id = "aws-us-east-2"
}

# The ZIP must contain an index.mjs at the root whose default export has a fetch handler.
# In production, build the ZIP in your CI pipeline.
data "archive_file" "function" {
  type        = "zip"
  output_path = "${path.module}/function.zip"

  source {
    filename = "index.mjs"
    content  = <<-EOT
      export default {
        fetch: () => new Response("Hello world!"),
      };
    EOT
  }
}

resource "neon_function" "example" {
  project_id    = neon_project.example.id
  branch_id     = neon_project.example.branch.id
  slug          = "hello"
  runtime       = "nodejs24"
  name          = "hello"
  zip_file_path = data.archive_file.function.output_path

  # Redeploys when the code changes, even though the ZIP path stays the same.
  source_code_hash = data.archive_file.function.output_base64sha256

  environment_variables = {
    LOG_LEVEL = "info"
  }
}
```

## Schema

### Required

- `branch_id` (String) The Neon branch ID.
- `project_id` (String) The Neon project ID.
- `runtime` (String) Runtime for the function. Currently only `nodejs24` is supported. Changing it deploys the function again.
- `slug` (String) Branch-unique identifier for the function. Must be 1 to 20 lowercase letters or digits, with no hyphens, underscores, or uppercase letters. Forms the invocation URL host together with the branch ID.

### Optional

- `environment_variables` (Map of String, Sensitive) Environment variables to expose to the function. The API never returns their values. Terraform stores configured values in state and marks them sensitive. Changing them deploys the function again.
- `name` (String) Free-form display name for the function. Updatable in place.
- `source_code_hash` (String) Hash of the ZIP archive, for example `filebase64sha256("function.zip")`. Set it so that a new archive at the same `zip_file_path` deploys the function again.
- `zip_file_path` (String, Sensitive) Path to a local ZIP archive of the function source. Required on create. Changing it deploys the function again.

### Read-Only

- `created_at` (String) RFC3339 timestamp at which the function was created.
- `current_deployment_id` (Number) Monotonic deployment version number of the most recent deployment, regardless of build status.
- `environment_variable_names` (List of String) Names of the function's environment variables. Values are never returned by the API.
- `id` (String) Composite ID of the form <project_id>/<branch_id>/<slug>.
- `invocation_url` (String) URL at which the function is invoked.



## Import

The Neon Function can be imported to the terraform state by its composite identifier that consists of
`ProjectID`, `BranchID` and the function `slug` separated by a forward slash.

Import using the [import block](https://developer.hashicorp.com/terraform/language/import):

For example:

```hcl
import {
  to = neon_function.example
  id = "curly-poetry-30604233/br-snowy-mountain-a5jkb18i/hello"
}
```

Import using the command `terraform import`:

```commandline
terraform import neon_function.example "curly-poetry-30604233/br-snowy-mountain-a5jkb18i/hello"
```
